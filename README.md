# 5S Launcher

Пульт управления корпоративным прокси для Windows: одно окно, в котором видно
состояние SSH-туннеля, HTTP-моста и системного прокси, и три кнопки, чтобы всем
этим управлять. Все служебные процессы работают в фоне, без окон терминала.

Ключевая особенность — **умная маршрутизация**: российские сайты открываются
напрямую, весь остальной трафик идёт через корпоративный прокси.

## Как это устроено

```
браузер / приложения
        │
        ├── сайт из списка исключений (.ru, .su, .by, .рф, VK, Яндекс, ...) ──► напрямую
        │
        └── всё остальное
                 │
                 ▼
        системный прокси Windows (127.0.0.1:8118)
                 │
                 ▼
        gost — мост HTTP → SOCKS5
                 │
                 ▼
        SSH-туннель (ssh -D 5555 на корпоративный прокси)
                 │
                 ▼
              интернет
```

Windows умеет ходить только через HTTP-прокси, а туннель даёт SOCKS5 — поэтому
между ними стоит `gost`. Список исключений прописывается в системную настройку
прокси, поэтому правило действует на браузеры и большинство приложений.

## Состав

| Файл | Назначение |
|---|---|
| `5s-launcher.ps1` | Полный пульт (WPF-окно с журналом) |
| `5s-widget.ps1` | Виджет: компактная панель на рабочем столе |
| `5s-launcher.vbs`, `5s-widget.vbs` | Тихий запуск без мелькания консоли |
| `tools/5s-common.ps1` | Общие настройки и логика: **список исключений живёт здесь** |
| `tools/5s-launcher.exe` | Собирается автоматически: иконка для панели задач и цель для закрепления |
| `tools/start-tunnel.bat` | SSH-туннель `-D 5555` с автоперезапуском |
| `tools/tunnel.example.cmd` | Шаблон локального конфига с SSH-логином |
| `tools/tunnel.local.cmd` | **Ваш** SSH-логин. В `.gitignore`, не коммитится |
| `tools/gost.exe` | Мост HTTP (8118) → SOCKS5 (5555) |
| `tools/proxy-smart.ps1` | Включить/выключить умный прокси из командной строки |
| `tools/icon-1a.ico`, `tools/logo.png` | Иконка приложения и логотип в шапке |

## Требования

- Windows 10/11, PowerShell 5.1 или 7
- .NET Framework 4 (для сборки `5s-launcher.exe`, есть в системе по умолчанию)
- SSH-доступ к прокси-серверу по ключу (пароль в фоне ввести некуда)

Логин и адрес прокси-сервера хранятся только в `tools\tunnel.local.cmd` —
он в `.gitignore`, поэтому в репозиторий не попадает.

## Установка

1. Склонировать репозиторий в любую папку (пути определяются автоматически).
2. Положить `gost.exe` в `tools\` — https://github.com/go-gost/gost/releases
3. Скопировать `tools\tunnel.example.cmd` → `tools\tunnel.local.cmd`
   и вписать туда свой SSH-логин (`SSH_TARGET=логин@сервер`).
   Этот файл в `.gitignore` и в репозиторий не попадает.
4. Запустить `5s-launcher.vbs` (полный пульт) или `5s-widget.vbs` (виджет).

Закрепить на панели задач: запустить пульт → правый клик по его кнопке →
«Закрепить». Иконка берётся из `tools\5s-launcher.exe`, который пульт собирает
сам при первом запуске.

## Использование

Кнопки в окне включают и выключают каждый слой независимо:

- **SSH-туннель** — поднимает `start-tunnel.bat` в фоне, порт 5555
- **Мост gost** — HTTP-прокси на 8118 поверх туннеля
- **Системный прокси** — прописывает 127.0.0.1:8118 в настройки Windows
  вместе со списком исключений

Точка слева от строки показывает состояние: синяя — работает, терракотовая —
остановлено. Статус обновляется каждые 3 секунды. Ошибки запуска пишутся в
Журнал, вывод gost — в `tools\gost.log`.

Правильный порядок включения — сверху вниз: туннель → мост → прокси.
При выключении наоборот.

## Виджет на рабочем столе

`5s-widget.vbs` — та же панель в компактном виде, живёт прямо на рабочем столе:

- по умолчанию под всеми окнами: виден на свободном рабочем столе, ничего не
  перекрывает, кнопки на панели задач и записи в Alt+Tab нет;
- «Свернуть все окна» (Win+D) его не прячет — сторож возвращает виджет обратно,
  не перехватывая фокус;
- перетаскивается мышью за любое место, позицию запоминает;
- правый клик: открыть полный пульт, переключить «Поверх всех окон»
  (по умолчанию выключено), автозапуск при входе в Windows, закрыть.

Настоящим виджетом Windows 11 это быть не может: панель виджетов закрыта для
сторонних программ (нужна упаковка MSIX и регистрация провайдера). Вариант
«приклеить к рабочему столу» (как в Rainmeter) на Windows 11 24H2 не работает:
Проводник не отдаёт окно рабочего стола в родители, поэтому виджет сделан
обычным окном со сторожем.

## Настройка маршрутизации

Список «ходить напрямую» — переменная `$RuBypass` в `tools\5s-common.ps1`.
Он один на всех: пульт, виджет и `proxy-smart.ps1` берут его оттуда.

```powershell
$RuBypass = @(
    "*.ru"; "*.su"; "*.by"; "*.xn--p1ai"    # .рф в punycode
    "vk.com"; "*.vk.com"; "*.userapi.com"
    "*.yandex.net"; "*.yastatic.net"
    ...
)
```

Если российский сайт на нерусском домене всё же пошёл через прокси — добавьте
его маску сюда, и правило подхватится везде.

`$InternalBypass` — внутренняя сеть (172.20.*) и localhost, всегда напрямую.

## Известные ограничения

- Маршрутизация работает по доменам, а не по геолокации IP. Для точного
  разделения нужна GeoIP-база (gost или sing-box с geoip-правилами).
- Приложения со своими настройками прокси (например, Firefox по умолчанию)
  системные исключения не читают — настраивать отдельно.
- Окно ssh скрыто, поэтому запрос пароля или подтверждение ключа показать
  негде. Если туннель не поднимается — запустите `tools\start-tunnel.bat`
  вручную и посмотрите, что он спрашивает.
