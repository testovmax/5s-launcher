# 5S Launcher

Пульт для Windows: одно окно, из которого включается туннель до своего сервера и системный прокси. Туннель бывает двух видов — SSH или VLESS. Поверх него всегда один и тот же локальный мост, поэтому браузер в обоих случаях ходит на `127.0.0.1:8118`.

Окно фиксированного размера, без консоли. Служебные процессы работают в фоне.

## Как это устроено

```
браузер / приложения
        │
        ├── галка «Маршрутизация» включена и сайт есть в bypass.txt ──► напрямую
        │
        └── остальной трафик
                 │
                 ▼
        системный прокси Windows (127.0.0.1:8118)
                 │
                 ▼
        gost — мост HTTP → SOCKS5, только localhost
                 │
                 ▼
        локальный SOCKS 127.0.0.1:5555
                 │
        ┌────────┴─────────┐
        │                  │
        ▼                  ▼
   ssh -D              Xray (VLESS)
        │                  │
        └────────┬─────────┘
                 ▼
              сервер
```

Windows отдаёт приложениям HTTP-прокси, а туннель заканчивается SOCKS5. Между ними стоит `gost`. Он слушает только `127.0.0.1:8118`.

SSH поднимает `ssh -D 127.0.0.1:5555`. VLESS поднимает Xray с входящим SOCKS на том же порту. Мост и системный прокси от протокола не зависят.

Исходящее соединение к серверу уходит с адреса обычного сетевого адаптера, мимо Clash/VPN-туннеля с адресами `198.18.*`, если такой адаптер есть.

## Окно

Размер 560×560, менять его нельзя.

- **Сервер** — список подключений. Рядом кнопка **···**: добавить, изменить, удалить. Смена сервера при живом туннеле перезапускает только туннель.
- **Туннель** — строка вида `SSH:` или `VLESS:`. Кнопка запускает и останавливает выбранный сервер. Рядом показывается ping до хоста, обновление примерно раз в 5 секунд.
- **Прокси** — одна кнопка на мост gost и системный прокси. «Выключить» есть только когда работают оба. Если мост уже есть, а системный прокси нет, кнопка «Включить» дописывает его. Без туннеля прокси не включается.
- **Маршрутизация** — галка. Включена: адреса из `tools\bypass.txt` идут напрямую. Выключена: весь внешний трафик идёт через прокси. `localhost`, `127.0.0.1` и сеть `172.20.*` всегда напрямую, иначе мост зациклится на себя.
- **Открыть список** — открывает `tools\bypass.txt`. После правки галку нужно переключить, файл читается заново в этот момент.
- **Журнал** — что сделали кнопки и короткая причина, если туннель не поднялся. Кириллица в тексте ошибок читается как есть.

Синяя точка — слой работает. Терракотовая — остановлен или включён только наполовину. Статус обновляется каждые 3 секунды.

Порядок включения: туннель, затем прокси. Выключение — наоборот.

Если туннель обрывается сам, а не кнопкой «Остановить», пульт закрывает настольное приложение Claude (`Claude.exe` из пакета Windows и `cowork-svc.exe`). Консольный `claude.exe` не трогает.

## Серверы

Файл `tools\connections.json` в git не попадает. Туда пишутся имя, протокол, адрес и ключ или ссылка.

**SSH.** В диалоге: имя, протокол SSH, `login@host`, путь к ключу. Ключ можно не указывать, если OpenSSH и так берёт его сам. Пароль в фоне ввести некуда: `ssh` запускается с `BatchMode`. Если туннель не поднимается, текст ошибки попадает в журнал и в `tools\tunnel.log`.

**VLESS.** В диалоге выбирается протокол VLESS и вставляется ссылка `vless://...`. Поддерживаются TCP, TLS, Reality, WebSocket и gRPC — те параметры, которые есть в ссылке (`security`, `sni`, `fp`, `pbk`, `sid`, `flow`, `path` и остальные). Xray слушает SOCKS на `127.0.0.1:5555`. Ссылка и сгенерированный конфиг лежат в `tools\vless.link` и `tools\vless.json`, оба файла локальные.

Первый запуск, если json ещё нет, один раз переносит серверы из `tools\tunnel.local.cmd`.

## Установка

Нужны Windows 10/11 и PowerShell 5.1 или 7. Для SSH — клиент OpenSSH и ключ. Для VLESS — `tools\xray.exe`. Для моста — `tools\gost.exe`.

1. Положить проект в любую папку. Пути считаются от неё.
2. Скачать [gost](https://github.com/go-gost/gost/releases) и положить `gost.exe` в `tools\`.
3. Для VLESS скачать [Xray-windows-64.zip](https://github.com/XTLS/Xray-core/releases) и положить `xray.exe` в `tools\`.
4. Запустить `5s-launcher.vbs`.
5. Через **···** добавить сервер.

Закрепить на панели задач: запустить пульт, правый клик по кнопке, «Закрепить». При первом запуске, если файла ещё нет, собирается `tools\5s-launcher.exe` — у него иконка приложения. Для сборки нужен .NET Framework 4, он есть в Windows.

Из командной строки, без окна:

```powershell
powershell -ExecutionPolicy Bypass -File tools\proxy-smart.ps1       # туннель, мост и прокси
powershell -ExecutionPolicy Bypass -File tools\proxy-smart.ps1 -Off  # выключить мост и прокси, туннель не трогать
```

Галка маршрутизации берётся из `connections.json`.

## Список «напрямую»

`tools\bypass.txt`, одна маска в строке. Строки с `#` — комментарии.

```
example.com
*.example.com
```

Обычно нужны обе строки. Файл перечитывается при включении прокси и при переключении галки. Перезапускать пульт не нужно. Если страница всё равно идёт старым путём, обновите её через Ctrl+F5: браузер держит уже открытое соединение.

Маршрут режется по имени сайта, не по стране IP.

## Ограничения

- Firefox со своим прокси системный список не читает.
- Ping в строке статуса — это ICMP до хоста. Он может проходить, когда VLESS или SSH трафик ещё не идут, и наоборот.
- Синяя точка туннеля значит, что локальный порт 5555 открыт. Если сервер VLESS отклоняет сессию, порт всё равно слушается, а сайты открываются с `ERR_CONNECTION_CLOSED`. Текст отказа смотрите в `tools\tunnel.log`.
- Ссылка VLESS должна совпадать с текущими UUID, ключом Reality, short id, SNI и flow на сервере.
